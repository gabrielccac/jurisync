# Codebase review and restructuring plan (2026-11-09)

Read-only review of the whole package by four reviewers (PJe; Eproc/e-SAJ/Projudi; ADVBOX/Juridiq/DJEN; core,
hosted and packaging). Nothing below is implemented yet unless marked. IDs point to the reviewers' findings:
`P` PJe, `E` Eproc/e-SAJ/Projudi, `A/J/D/N/S/X` ADVBOX/Juridiq/DJEN, `C` core/hosted.

## Already done in this round

- ADVBOX: one `advbox_search_tasks` (free text + every Tarefas filter) replaces `advbox_list_activities` and
  `advbox_find_tasks`; `advbox_task_filters`; fixed the completed value (`finalizados`), the inverted
  important/urgent flags, the 413 refusal message, and lawsuit totals/icon text. Validated live (Victor).

- Eproc TJSP: all seven queues through the state endpoint (the old "open deadlines" read only today's).

## 1. Safety first (high severity, small)

| ID | Problem | Fix |
|---|---|---|
| P1 | `pje_get_process(documentIds)` reads documents without the pending-ciência gate | Remove `documentIds` from it; documents only through `pje_read_documents` |
| P2 | The ciência gate fails open when the Expedientes tab/API cannot be read | Refuse unless `acknowledgeCiencia` or the allow policy |
| E1 | No cool-down after a rejected login: retries can lock the lawyer's account | Per (tenant, portal) cool-down in `SessionPool` after an auth failure, max 2 failures |
| C1 | Root `.env` fills any secret a customer lacks (another customer's QR/A1 can be used) | With `JURISYNC_CUSTOMER` set, load only that customer's `.env`; split the root file |
| E3 | e-SAJ bridge shares one Chrome profile (cookies) across tenants | Temporary profile per call, or clear cookies in `finally` |
| E4 | `esaj/recaptcha.py` mints reCAPTCHA tokens without a browser | Decided 2026-11-09: keep e-SAJ as it is (out of this plan) |
| P3 | PJe filing jobs keyed by `runId` only, not tenant | Key by (tenant, runId); move filing out of the hosted server (see 3) |
| A1 | ADVBOX task creation can duplicate on retry | `dedupeKey` (e.g. DJEN id) checked before creating; no replay after ambiguous failure |
| A2 | Staged `/s3` files are not cleaned when task creation fails (they attach to the next task) | Delete staged codes on failure |
| A3 | `complete_task` / `delete_task` take only a postId | `dryRun` + `expectComments` like `update_task` |
| D1 | DJEN deadline calendar ends 2026-12-19 and is JFPE-only | 2027 calendars, `court` parameter, clear error per court |
| C5 | Errors can leak local server paths | Path redaction in `sanitize_diagnostics` |

## 2. Performance

| ID | Problem | Fix |
|---|---|---|
| P5 | Every process tool repeats the 4-request search + all timeline pages | Per-tenant cache of process id/token (minutes); `include=` so documents/ato skip the timeline |
| P6, P7 | Inbox opens empty inboxes; counters expand every bucket (62 requests) | Skip `count == 0`; `bucket` argument instead of `regions=true` |
| P8 | KZ enrichment runs before the filters | Filter first, enrich survivors |
| P4 | Push returns 9,053 rows | `limit`/`offset`/`processNumber` |
| X1 | ADVBOX re-downloads members/workflows/steps every call; `is_pending` pages 6×100 | Per-tenant TTL cache; one check |
| X2 | ADVBOX folder download+OCR holds the office lock for minutes | Download/OCR outside the lock |
| D2 | DJEN saved searches run one after another | Parallel with copied context |
| J3 | Juridiq opens a new HTTP session per request | One session per tenant, token in memory |
| E2, C3 | Eproc login starts one Chrome per login with no limit; pools never evict | Global login semaphore, idle TTL/LRU |
| E12 | Eproc login fixed sleeps | Event waits |
| C14 | Selenium imported by every Eproc server start | Lazy import |

## 3. Tool surface (fewer, consistent tools)

- **PJe**: 6 read tools on the PJe server; the 5 draft tools move to a local-only `pje-filing` server (they fail
  remotely today). Drop `movement_candidates`; return each expediente once.
- **ADVBOX** (22 → ~14): one `advbox_reference(kind)` for members/workflows/steps/filters/partners (cached);
  one `advbox_fetch_files(mode=read|save)` instead of three download tools; drop `advbox_ensure_session`.
- **Juridiq**: merge `list_tasks` and `list_tasks_kanban`; one `juridiq_reference(kind)`; exact
  `find_lawsuit`; write tools gated per tenant at call time (J2).
- **DJEN**: keep 5; OAB supplementary variants on by default; window validation.
- **Eproc/e-SAJ/Projudi**: same argument names (`processNumber`, `documentIds`), same document tools
  (`*_read_documents`, `*_download_document`); remove the dead `esaj_list_intimacoes` and placeholder adapters.
- **All**: ISO dates in every input (ADVBOX converts internally), one list shape `{items, total, page, hasMore}`,
  one key convention (camelCase), text caps reported as truncated.

## 4. Structure (the base for the HTTP API)

```
src/jurisync/
  core/        settings (process config), credentials (tenant), errors (typed, stable codes),
               sessions (pool + TTL + login semaphore + cool-down), session_store (file | encrypted),
               http (LoggedSession: timeout, retries, request log), redaction, totp (reserve window)
  connectors/<system>/
               client/parsers/auth   portal mechanics
               service.py            plain functions with typed results, no MCP imports
               spec.py               ConnectorSpec: name, service, close, tenant_ready, write tools, secrets
  adapters/mcp  one create_server(spec), one error decorator
  adapters/api  HTTP routes from the same services
  hosted/      platform only (vault, store, OAuth, gate), driven by the registry
  registry.py  every connector's spec; serve, hosted, .mcp.json and setup derive from it
```

Key moves: typed error hierarchy replacing `success: False` dicts and broad `except` (C9, P10, E8); one
registry instead of four lists to keep in sync (C7); PJe JSF/KZ behind one `Backend` (P16); shared browser login
for Eproc/e-SAJ/Projudi (E13); one `CustomerProfile` parsed once (C12); per-tenant paths everywhere (C17);
encrypted session caches when hosted and no `cwd()` in the PJe cache identity (C10, P20).

## 5. Order

1. **Phase 0 (days)**: section 1 plus the small items of section 2 (P6, P7, P8, P4, D2, C14), the 2027
   calendar, dead code (CLI mains, `esaj_list_intimacoes`, DJEN `client.main`), tests for each fix.
2. **Phase 1 (1–2 weeks)**: errors, settings vs credentials, registry, CustomerProfile, cache-file helper,
   caches (P5, X1, J3), login semaphore/TTL/cool-down, tool-surface changes of section 3.
3. **Phase 2**: `service.py` per connector (DJEN and PJe reads first), then the HTTP API on the same services;
   tool-call audit and structured logs; Dockerfile; no `customers/` reads at runtime.
4. **Phase 3**: scale-out (shared session store, sticky workers, per-tenant limits).

Tool renames break the installed plugins and skills; ship them together per connector with the skill updates.
