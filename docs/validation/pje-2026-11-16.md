## Correções (branch `val/pje`)

1. **Processo pelo Acervo quando a busca pede CAPTCHA** (`connectors/pje/acervo.py`, `search.py`). A consulta
   `ConsultaProcesso/listView.seam` do TJRN 1G responde "A verificação de captcha não está correta" (reCAPTCHA
   invisível) e a do TJBA 1G chama um Tencent Captcha e devolve a tabela vazia. O painel do advogado abre o mesmo
   detalhe sem CAPTCHA: a aba Acervo lista os processos por jurisdição com o link "Autos Digitais"
   (`listProcessoCompletoAdvogado.seam?id=…&ca=…`), e a busca da própria listagem (`formAcervo:btPesqAc`) filtra a
   jurisdição aberta pelo número CNJ. Quando a busca normal é recusada por CAPTCHA, o conector abre cada jurisdição,
   busca o número e segue o fluxo comum (detalhe, linha do tempo, expedientes, conferência de ciência). Só posta a
   aba, o nó e o Pesquisar; os formulários de configuração da caixa nunca são enviados. No TJRN o processo da 1ª
   jurisdição sai em 4 requisições; um da 12ª em ~26.
2. **Aba Expedientes no TJBA** (`inbox.py`). O PJe 2.10 do TJBA abre o painel na aba Peticionar, sem a árvore de
   buckets. Se o painel não tem buckets e a aba Expedientes está inativa, o conector a seleciona (mesmo A4J do
   cabeçalho, parâmetros conferidos) antes de ler.
3. **Login legado TJRJ 2G no protocolo real do PJeOffice** (`auth/certificate.py`, `auth/signer.py`, `auth/a3.py`).
   Decompilado o PJeOffice Pro 2.5.16 (`PjeAuthenticatorTask`, `PjeWebClient`, `utils4j.Certificates`):
   - a tarefa `cnj.autenticador` assina `mensagem.getBytes(UTF-8)` com **MD5withRSA** (padrão quando a página não
     manda `algoritmoAssinatura`; o código já fazia isso);
   - envia `POST servidor + enviarPara` (`/2g/logarPJeOffice.seam?cid=…`) como **formulário**
     `application/x-www-form-urlencoded` com `assinatura` (base64) e `cadeiaCertificado` (base64), com o cookie da
     página e o header `versao` — o conector mandava JSON `{uuid, mensagem, assinatura, certChain}` (formato do SSO);
   - `cadeiaCertificado` é `CertPath.getEncoded("PkiPath")` do Java, que grava **da raiz para o titular**; o conector
     gravava titular primeiro, e o Java decodificava uma AC na posição 0 (conferido com o JRE do PJeOffice);
   - resposta `Sucesso` ou `Erro:<motivo>`; no sucesso o navegador abre `homePJeOffice.seam?cid=…`.
   Resultado: antes, "Verifique se o cartão ou token estão c…" (o servidor não achava os campos); com o formulário
   (1ª tentativa) e com a cadeia na ordem Java (2ª tentativa), "Certificado não encont…" (texto cortado pelo próprio
   portal): o servidor leu assinatura e cadeia e não achou usuário para o certificado da Ana Flávia. O payload do SSO
   (todos os outros portais) não mudou.
4. Mensagem clara para esse caso ("the portal found no user for this certificate… probably not registered").
