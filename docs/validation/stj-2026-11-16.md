## 1. Como o advogado acessa hoje

- **Central do Processo Eletrônico (CPE)**: `https://cpe.web.stj.jus.br/` (o antigo `cpe.stj.jus.br` redireciona para ele).
  É uma SPA React (`app.js`, ~14 MB, versão 2.6.28, build de 14/11/2026). A API fica em `https://cpe.web.stj.jus.br/api/...`.
- Formas de login que aparecem no bundle:
  1. **Certificado digital**: `POST https://cpe-auth.web.stj.jus.br/api/auth/cert` com corpo `{}`. O host exige
     certificado cliente no handshake TLS (sem certificado: `handshake failure`, alerta 40; o servidor não manda lista
     de CAs). **Sem MFA no login por certificado**: `processaResponseLogin(..., certificado=true)` pula o MFA.
  2. **CPF + senha** (`POST /api/auth`, senha em base64, reCAPTCHA invisível): depois vem MFA por TOTP, com QR gerado
     pelo STJ (`/api/auth/mfa`), ou por código enviado por e-mail (`/auth/confirmarEmailMfa`).
  3. **gov.br**: OAuth2/PKCE em `sso.acesso.gov.br` (client_id `cpe.web.stj.jus.br`, redirect `/govbr`), com troca
     do código em `POST /api/auth/govbr`.
  4. Também existem a chave de acesso (`/api/auth/chaveDeAcesso`, para partes sem cadastro) e o acesso pelo CNJ (`/api/auth/cnj`).
  **Não há** SSO PDPJ/Keycloak do PJe.
- A resposta do login traz `token`: um JWT HS de ~240 caracteres, com claims `sub` (CPF), `OAB` (lista), `created`
  e `exp` (~4 h). O front envia o JWT cru no cabeçalho `authorization` (sem `Bearer`) em todas as chamadas `/api`.
  Sem token, a API responde `401 Access Denied`. A exceção são `/info` e `/api/credenciado/isCredenciado/{cpf}`, que são públicos.
- Pré-requisito: o advogado precisa ser **credenciado** na CPE. Se não for, o primeiro login por certificado devolve
  `novoCredenciado=true` e o front leva para o cadastro (`/meuCadastro`). Isso conta como cadastro e não deve ser
  automatizado. O conector deve checar `isCredenciado` antes e recusar se for `false`. A Ana Flávia é credenciada
  (`novoCredenciado:false`, perfil `ADVOGADO` `GO051632`).

## 3. Intimações: de onde vêm

- O STJ intima advogados pelo **DJEN** (Comunica). Pela OAB GO 51632, tribunal STJ, saíram em outubro de 2026 2 intimações
  meio D: AREsp 3415877/MT (1005996-67.2025.8.11.0045, 13/10) e AREsp 3436926/GO (5267520-15.2026.8.09.0051, 26/10).
  O conector DJEN do repo já cobre isso (`djen_search_communications` com `tribunal=STJ`). O texto vem em tabela HTML,
  que `djen.normalize` já trata.
- A CPE **não tem caixa de intimações** como a do PJe. O que existe:
  - "Minhas publicações": é o DJe próprio do STJ, que é legado.
  - "Ciência antecipada": lista os atos sobre os quais o advogado pode dar ciência antes da publicação. Só ler a lista
    não registra nada; a ciência só é registrada no POST de inclusão.
  - "Vistas em aberto": aparecem para entes públicos.
  - O link para o Domicílio Judicial Eletrônico (PDPJ): é por onde pessoas jurídicas são citadas e intimadas.
- **Consulta pública** (`processo.stj.jus.br/processo/pesquisa`, `scon.stj.jus.br`) fica atrás do Cloudflare
  *managed challenge* (403 "Verificação automática"). Por HTTP não dá para usar sem navegador. Os links do DJEN para
  `processo.stj.jus.br/processo/dj/documento/?seq_documento=` respondem 200 sem o desafio (o teste usou um seq
  qualquer), então o texto da publicação continua acessível. A CPE autenticada é o caminho
  confiável para capa, andamentos e documentos.
- Conclusão: **DJEN para intimações** (já validado) e **CPE para enriquecer** (andamentos, partes, peças, PDF).

## 4. Fluxo de login testado (1 login, sem segredos no log)

1. Carrega o A1 (`core.certificate.load_a1` com `PJE_A1_P12`/`PJE_A1_PIN` do .env da anaflavia).
2. `requests.post("https://cpe-auth.web.stj.jus.br/api/auth/cert", json={}, cert=(cert.pem, key.pem))`, com o PEM
   temporário de `core.certificate.client_certificate`. Resposta: 200 JSON `{username, token, novoCredenciado:false, certificado{...}, error:null}`.
3. As chamadas seguintes vão para `cpe.web.stj.jus.br/api` com `authorization: <token>`. Não precisa de cookie.
   Também não precisa escolher perfil para ler: o perfil só entra no corpo dos POSTs de petição e ciência.

Funcionou com `requests` puro (sem curl_cffi/impersonate). Na API autenticada não houve Cloudflare nem WAF. Para A3, o
`core.mtls.fetch` (tlslite com o token) basta, porque só esse POST usa o certificado.

## 5. Plano de conector (`connectors/stj`)

1. `auth.py`: login mTLS (A1 por `requests`/`curl_cffi` `cert=`; A3 por `core.mtls.fetch`). Antes, checa
   `isCredenciado` e recusa `novoCredenciado`. Guarda o JWT no `session_pool` e renova quando faltarem menos de 10 min
   para o `exp` ou quando vier 401. Credenciais: `STJ_A1_P12`/`STJ_A1_PIN` com fallback para `PJE_A1_*`
   (`certificate.credential_names("STJ")`).
2. `client.py`: `list_processes(tramitando)`, `resolve(cnj|classe+número)`, `get_process(registro)` (capa, fases,
   partes, índice), `read_document(registro, sequencialPeca)` (autorização + PDF, depois texto via `core.document_text`),
   `pending_early_notice(registro)` (só a lista da ciência antecipada, nunca a inclusão).
3. `server.py` (MCP): `stj_list_processes`, `stj_get_process`, `stj_list_documents`, `stj_read_documents`. Intimações
   continuam no DJEN; o `djen` pode enriquecer pelo `stj_get_process` quando `resolve_portal` der `stj`.
4. Testes offline com fixtures JSON sanitizadas (formatos da seção 2) e lista de bloqueio dos endpoints de escrita.
5. Opcional: login por CPF+senha+TOTP (QR do STJ) para quem não tem A1. Exige o reCAPTCHA do login por senha, então
   provavelmente precisa de navegador. Não vale a pena enquanto houver A1.

Esforço: login e cliente, ~1 dia; servidor MCP, testes e integração com o DJEN, ~1 a 2 dias.
