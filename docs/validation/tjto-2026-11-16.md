## Correção no conector

`337561d Accept TJTO's mTLS certificate host and report it when unpublished`

- `certificate.require_login_url` rejeitava o redirect para `mtls.tjto.jus.br` (não é host SSO). Mesmo com o DNS
  publicado, o login por certificado falharia com `Unexpected eproc login redirect URL`. Agora o host é aceito só para
  `tjto-1g`/`tjto-2g`, só em `https`, e só nas páginas `<raiz>externo_controlador.php` e `<raiz>priv/login_cert.php`
  da raiz do próprio portal.
- Enquanto o nome não resolve, o login por certificado termina com mensagem clara: `TJTO certificate login host
  mtls.tjto.jus.br does not resolve (not published in DNS by the court); certificate login is unavailable until it is`.
- Testes offline (`tests/connectors/eproc/test_eproc_certificate.py`, fixture mínima sem dados pessoais): limite de
  host/caminho, fluxo clássico seguindo o host mTLS com o A1 até o código e o painel, e a mensagem de DNS. O passo
  depois do `mtls` (volta ao `eproc1` e tela de código) é suposição pelo padrão TJMG/TRF2; confirmar no primeiro login
  real.
- `uv run pytest -q --ignore=tests/live` e `ruff check`/`ruff format --check` passam.

## Pendências e recomendação

1. Certificado (caminho preferido, A1 + TOTP sem pessoa): depende do TJTO publicar `mtls.tjto.jus.br`. Sugestão: a
   cliente (Hérica) abrir chamado no TJTO informando que o botão "Certificado Digital" redireciona para um host sem
   DNS. Quando resolver: definir `TJTO_1G_CERT=true`/`TJTO_2G_CERT=true` no `.env` da Hérica (hoje o `portals.toml`
   dela declara `browser_totp` com usuário/senha) e fazer um login real; conferir `TJTO_2G_2FA_QR` (só o de 1G está
   preenchido; o 2G pode depender de `TJTO_2G_OTP_PROFILE_MATCH`).
2. Senha: o CAPTCHA é simples (4 dígitos sobre ruído leve). Dá para resolver com OCR local ou com o mesmo modelo de
   visão do `core/awswaf.py`, mas isso é decisão de produto (resolver CAPTCHA de tribunal) e ficou fora desta rodada.
   Só Dênis tem `TJTO_*_USERNAME/PASSWORD`; Hérica e Allan não têm senha do TJTO.
3. O login por senha via HTTP (`http_login`) posta em `acao=login_cert` como no TJMG; no TJTO isso também vai ao
   `mtls` e falha com "eproc redirected to another host". Hoje é irrelevante (o CAPTCHA trava antes), mas se o CAPTCHA
   for automatizado o caminho por senha precisa postar em `index.php` e tratar `hdnStrTela=captcha`.
